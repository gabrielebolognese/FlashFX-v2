# FlashFX — 2.5D System (cards-in-space + camera, After Effects model)

## 0. Goal

A **full-scale, bulletproof 2.5D** system modeled on After Effects' Classic 3D: any layer can be
promoted to a **3D layer** (a flat "card" that gains a Z position and X/Y/Z rotation and lives in a 3D
space), and a **Camera** views that space with real perspective. Cards **occlude** each other by depth
(painter's algorithm), the camera **moves and keyframes**, and there's optional **depth of field**. This
is the stepping-stone to real 3D (lights/shadows, intersection, extrusion) — those are explicitly out of
scope here and noted at the end.

Why this is the right increment: it reuses the entire existing per-layer-quad renderer — each layer is
already a textured/generated quad drawn with a transform; 2.5D just replaces the **2D affine** transform
with a **camera-projected 4×4 (MVP)** and adds a depth sort. No new layer-rasterization, no geometry.

---

## 1. How After Effects does it (feature/UI research)

### 1a. The **3D Layer** switch
A per-layer toggle (the cube icon in the timeline's switches column). Flipping it turns a 2D layer into a
3D layer: its transform properties gain a **Z** axis and it participates in the 3D scene + camera. 2D and
3D layers coexist in one comp (2D layers are "flat", always facing the camera at their stacking depth).

### 1b. 3D **Transform properties** (what the layer gains)
Per 3D layer, the Transform group becomes:
- **Anchor Point** — X, Y, Z
- **Position** — X, Y, Z
- **Scale** — X, Y, Z % (Z is a no-op for a flat card but present)
- **Orientation** — X, Y, Z ° (absolute orientation, interpolates as a unit quaternion → no gimbal flips)
- **X Rotation / Y Rotation / Z Rotation** — each ° + whole revolutions (relative, keyframe-friendly)
- **Opacity**
- **Material Options** (Casts/Accepts Shadows, Accepts Lights, Ambient/Diffuse/Specular/Shininess/Metal)
  — only relevant with **lights**; **out of scope for 2.5D core**.

UI: the inspector splits Position into three scrubbable fields (X Y Z), same for Anchor/Scale, and shows
Orientation + separate X/Y/Z Rotation rows, each keyframeable (stopwatch).

### 1c. The **Camera** (a layer)
Created via **Layer ▸ New ▸ Camera**, which opens a **Camera Settings dialog**:
- **Type**: One-Node (free / orientation-aimed) or Two-Node (aims at a **Point of Interest**).
- **Preset**: 15mm … 200mm + Custom (drives the lens).
- **Zoom / Angle of View / Focal Length / Film Size / Units** — all coupled (change one, others update).
- **Depth of Field**: Enable, **Focus Distance**, **Aperture**, **F-Stop**, **Blur Level**.

Camera **layer properties** (keyframeable, parentable, like any layer):
- **Point of Interest** (X,Y,Z) [two-node], **Position** (X,Y,Z), **Orientation**, **X/Y/Z Rotation**,
- **Zoom**, **Depth of Field**, **Focus Distance**, **Aperture**, **Blur Level**, **Iris** (shape/rotation/
  roundness/aspect/diffraction — bokeh; advanced).

The **active camera** = the top-most enabled Camera layer; with none, AE uses a fixed **default camera**
whose FOV/distance make a layer at Z=0 render at exactly its 2D size (so toggling 3D on a lone layer
changes nothing until it moves in Z or the camera moves).

### 1d. **Camera views & gizmo** (Composition panel)
- A **3D View** dropdown: **Active Camera**, Front, Left, Top, Back, Right, Bottom, **Custom View 1–3**.
  Orthographic/utility views for placing layers in depth; the render is always through the Active Camera.
- **3D transform gizmo** on the selected layer: colored **axis arrows** (X red / Y green / Z blue) to
  translate, **rotation rings** to rotate, and a **scale** mode. Local vs World vs View axis modes.
- **Draft 3D** toggle — fast preview (no DOF, no shadows).
- Orbit / Pan / Dolly tools to fly the Custom views.

### 1e. **Renderer modes** (occlusion model)
- **Classic 3D** (what 2.5D IS): flat cards, **painter's algorithm** z-sort — layers don't physically
  intersect; a layer is drawn wholly in front of or behind another by its anchor depth. Fast, predictable.
- Ray-traced 3D / Cinema 4D: real intersection, extrusion, reflections — **out of scope**.

### 1f. **Lights** (New ▸ Light) — Parallel/Spot/Point/Ambient, casting shadows on 3D layers. **Out of
scope for 2.5D core** (belongs with real 3D / material options).

**2.5D core = §1a–1e minus material/lights:** 3D layer toggle → Z + X/Y/Z rotation/orientation → cards in
space; a Camera layer (position, POI, zoom/FOV, optional DOF) → perspective; painter's z-sort → occlusion;
inspector 3D sliders + camera settings + 3D-view dropdown + gizmo. Lights/intersection are the bridge to
real 3D.

## 2. Codebase grounding (what we extend — verified)

- **Transform is strictly 2D** (`core/types.ts:76`): `position`(vec2), `rotation`(scalar = Z), `scale`
  (vec2), `anchorPoint`(vec2), `opacity`. `ResolvedTransform` (`types.ts:1181`): `positionX/Y, rotation,
  scaleX/Y, anchorX/Y, opacity`. Evaluated by `resolveTransform` (`interpolation.ts:308`).
- **Parenting is a 2D affine** — `composeTransforms(parent, child)` (`interpolation.ts:471`) does
  scale → rotate-Z → translate. This is the function that must become a **4×4 matrix compose** for 3D.
- **The renderer is per-layer quads**: the image/pattern vertex shader (`renderer.ts:818`) maps a unit
  quad → local (×quadSize) → rotate-Z about anchor → translate by quadPos → **NDC (y-down)**. Every layer
  type (shape/text/image/pattern/…) draws this way. 2.5D replaces this 2D math with an **MVP mat4**.
- **No mat4, no camera, no Z, no depth buffer anywhere.** The `is3D` flag exists on every layer type but
  is **dead** (`getIs3D` has zero call sites; the renderer never reads it; the "Draft 3D" button is
  disabled "no 3D layers yet"). The cloner packs a 2D affine into a mat4 but there's no real 3D math.
- **Layer-type system** (for the Camera layer) is well-trodden — the 9-touch-point checklist proven by
  particle/fieldSampled/generativePattern (types → factory → resolve → renderer → validation whitelist →
  store → toolbar → inspector → timeline). A `camera` layer follows it (but resolves to camera matrices,
  not a drawn quad).
- **Inspector Transform UI** (`Inspector.tsx`) has Position/Rotation/Scale/Opacity rows via `DragInput`
  with keyframe stopwatches — the pattern to extend to X/Y/Z. **Timeline switches** live in
  `timeline/TrackRow.tsx` (eye/mute/solo/compress) — where the 3D-layer cube toggle goes. **Viewport
  overlays** (`TransformOverlay`, bounding box) are where the 3D gizmo + camera-view dropdown attach.

## 3. The technical approach (how to make depth in TS/WebGPU)

### 3a. Matrix core — new `src/core/mat4.ts` (PURE, harness-tested)
Column-major 4×4: `identity, multiply, translate(x,y,z), rotateX/Y/Z(rad), scale(x,y,z), compose(TRS),
perspective(fovY, aspect, near, far), lookAt(eye, target, up), transformPoint(m, v3)→v4`, and a
`fromEuler`/`fromOrientation` for orientation. All pure functions — fully verifiable here.

### 3b. Data model — extend `Transform` (backward-compatible)
Add optional 3D properties (absent ⇒ treated as 0, so all existing 2D layers are unchanged):
`positionZ`, `rotationX`, `rotationY` (existing `rotation` stays as Z), and `orientation` (vec3, for AE's
quaternion-interpolated absolute orientation) — Milestone-gated (positionZ + X/Y rotation first,
orientation later). `ResolvedTransform` gains `z, rotationX, rotationY` (+ optional orientation). A layer
is 3D iff `is3D === true` (finally wiring the dead flag).

### 3c. 3D parenting — a matrix compose path
When a 3D layer (or its ancestor) is 3D, resolve each layer to a **local model matrix** (from TRS +
anchor) and compose down the parent chain via `mat4.multiply` (replacing `composeTransforms` for the 3D
case; 2D layers keep the cheap affine path). Store the resulting **world matrix** on the resolved layer.

### 3d. Camera — a `camera` layer type + resolved matrices
A `camera` layer (position vec3, pointOfInterest vec3 or orientation, zoom→FOV, DOF params). Resolve picks
the **active camera** (topmost enabled camera layer; else a **default camera** matching AE's "Z=0 renders
1:1" — `eye = (cx, cy, -zoom)`, `target = (cx, cy, 0)`, `fovY = 2·atan(compH/2 / zoom)`). Produce **View**
(`lookAt`) and **Projection** (`perspective`, aspect = compW/compH) once per frame; attach to the frame.

### 3e. Renderer — MVP vertex + painter's z-sort (GPU; guarded)
- Per 3D layer, compute `MVP = P · V · World` (CPU, in resolve/render prep) and pass it as a **mat4
  uniform** to the vertex shader; the vertex transforms the quad's 4 corners by MVP → clip space (the
  perspective divide gives foreshortening). 2D layers keep the existing 2D vertex path.
- **Occlusion = painter's algorithm:** sort 3D layers by their **camera-space Z** (anchor depth), draw
  **far → near**. 2D layers composite at their track stacking order (interleave: a 3D layer's sort key is
  its depth; 2D layers keep track order). This matches AE Classic 3D (no intersection).
- **Coordinate care:** the renderer is **y-down**; the camera/projection must use a consistent handedness
  (left-handed y-down, or flip Y in projection) so text isn't mirrored and rotations go the intuitive way.
  This is the #1 correctness trap — nail it in M2 with a known-good test scene.
- **Guarded like the pattern pipeline:** the 3D path is additive; if MVP/sort has a bug it affects only 3D
  layers, and a `is3D`-off comp renders byte-identically through the untouched 2D path.

### 3f. Depth of field (later milestone)
Per-layer blur amount = `f(|cameraZ(layer) − focusDistance|, aperture)`; drive the **existing blur
pipeline** per layer. Reuses shipping machinery; no new pass.

### 3g. Occlusion upgrade (later): a **depth buffer** for real intersection (beyond painter's) — this is
the boundary into "real 3D".

## 4. Milestones (bulletproof, full-scale)

Each milestone lists what's **harness/tsc-verifiable here** vs **browser-only (WebGPU)**. The GPU parts
are additive + guarded so they can't regress the 2D renderer.

- **M0 — Math + data model (fully verifiable).** `core/mat4.ts` + `verify:mat4` (identity, multiply,
  perspective, lookAt, transformPoint, compose associativity). Extend `Transform`/`ResolvedTransform` with
  `positionZ/rotationX/rotationY` (default 0), `resolveTransform` evaluates them, `is3D` becomes the gate.
  Validation/serialization round-trip the new fields. **No visual change yet.**
- **M1 — 3D parenting + camera math (verifiable).** Matrix model-compose for 3D layers; `camera` layer
  type (+ the 9 touch-points, resolves to View/Projection not a quad); the default camera; active-camera
  selection. `verify:camera3d` (default camera keeps Z=0 at 1:1; lookAt/perspective outputs; parent-chain
  compose). **Still no visual change** (renderer doesn't consume it yet).
- **M2 — Renderer: MVP + z-sort (BROWSER).** Per-3D-layer MVP uniform + vertex transform; painter's-order
  depth sort; 2D/3D interleave. Guarded/isolated. *Validate in Chromium: a 3D card at +Z is smaller, at an
  X-rotation shows perspective, two cards occlude by depth; a 2D comp is unchanged.*
- **M3 — UI (mostly verifiable).** 3D-layer **cube toggle** (TrackRow switches); inspector **X/Y/Z**
  Position/Rotation/Orientation rows (keyframeable); **New Camera** button + **Camera Settings** panel
  (zoom/FOV/DOF); **3D View** dropdown (Active/Front/Top/Left/Right/Custom); camera layer in the timeline.
- **M4 — Camera movement + gizmo (BROWSER for gizmo).** Keyframeable camera (position/POI/zoom animate);
  the **3D transform gizmo** (axis arrows + rotation rings, local/world/view modes); orbit/pan/dolly the
  Custom views; one-node vs two-node cameras.
- **M5 — Depth of field + draft (BROWSER).** Depth-based DOF blur via the existing blur pipeline; Draft 3D
  fast path; camera focus-pull keyframing.
- **M6 — Hardening (verifiable + browser).** Full persistence round-trip harness for 3D transforms +
  camera; edge cases (3D child of 2D parent and vice-versa, precomp-in-3D, collapsed transforms, extreme
  FOV, layers behind camera / near-plane clipping); perf pass (MVP caching, sort stability).

**Boundary → real 3D (separate plan):** a **depth buffer** for true intersection, **lights + shadows**
(material options), **extruded/geometry** layers, and a ray-traced renderer.

## 5. Risks & correctness traps

- **GPU is unverifiable here** — M2/M4/M5 (renderer, gizmo, DOF) need a WebGPU session; write against the
  known-good vertex/pipeline templates, guard so 3D-off comps are byte-identical, validate visually.
- **Handedness / y-down** — the projection + view must agree with the renderer's y-down NDC or text
  mirrors and rotations invert. Pin it with a reference scene in M2 before building UI on top.
- **2D/3D interleave & z-sort stability** — mixing flat and 3D layers, and stable sorting when depths tie,
  needs a defined rule (3D by camera-Z, 2D by track order); flicker if unstable.
- **Default-camera parity** — get `zoom↔FOV` and eye distance right so toggling 3D on a still layer is a
  no-op (AE's behavior); otherwise every layer jumps when made 3D.
- **Parenting semantics** — a 2D layer parented to a 3D one (and vice-versa), and precomps as 3D cards,
  must compose predictably; matrix path only for the 3D subtree.
- **Orientation vs rotation** — AE interpolates Orientation as a quaternion (no gimbal lock) but X/Y/Z
  Rotation as separate scalars; support both, and their sum, to match AE.
- **Persistence** — every new transform field + the camera layer must hit the validation whitelist or
  they're silently stripped on save/load (the class of bug that bit cloner/precomp/patterns).
- **Performance** — one mat4 multiply + one sort per frame is trivial; the cost is correctness, not speed.
